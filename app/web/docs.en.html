SupplierHub API

Top up Steam for your customers automatically. You fund your balance with crypto, orders are paid from that balance, and a webhook tells you how each one went.

1
Get a keySign in on the website with Telegram → profile menu → “API for partners” → “Create key”.
2
Fund your balanceOn the website or with POST /deposits — USDT, BTC, ETH, TON and more.
3
Create ordersPOST /orders charges your balance and tops up Steam.

Basics

Base URL: {{base}}/api/v1. Send your key in the X-API-Key header. Requests and responses are JSON (UTF-8). A successful response contains "ok": true; an error has "ok": false and a message in error. Messages follow your Accept-Language header: en gets English, anything else Russian.

curl {{base}}/api/v1/me -H "X-API-Key: SH-your_key" -H "Accept-Language: en"
CodeMeaning
200Success
400Invalid parameters: the message is in error, details for each field in fields. Unknown fields are rejected rather than ignored; amounts go as a string or a number with at most 2 decimal places
401Missing or invalid key
402Not enough balance — the response includes balance_usd and required_usd
403The IP isn't on the key's allowlist, or the account is blocked
404Not found
429Too many requests (the limit is 120 per minute per key)
503Service temporarily unavailable — try again later

Dollar amounts are strings with up to 6 decimal places ("12.249635"), so no precision is lost.

POST/steam/check

Checks whether a Steam account can be topped up. It takes the login the customer signs in with, not their profile nickname.

curl -X POST {{base}}/api/v1/steam/check -H "X-API-Key: SH-…" -H "Content-Type: application/json" \
  -d '{"steam_login": "mylogin"}'

{ "ok": true, "steam_login": "mylogin", "valid": true }

Orders

POST/orders

Creates a Steam top-up and charges its cost to your balance straight away.

FieldTypeDescription
steam_loginstringSteam login, 3–64 characters (Latin letters, digits, _ - .)
amountnumber | stringThe amount to add, in currency
currencystringRUB, KZT, UAH or USD (the Steam account's currency)

Balance

POST/deposits

An invoice for funding your balance. Send exactly amount of the coin to address on the given network within 30 minutes — the unique amount is how we recognise your payment. For TON, also put comment in the transfer's comment field.

{"amount_usd": 100, "method": "usdt_trc20"}

{ "ok": true, "deposit": { "id": "DP4M9QX2KA", "status": "pending", "usd": "100.00", "received_usd": "0.00",
  "method": "usdt_trc20", "coin": "USDT", "network": "TRC20", "network_title": "TRON",
  "address": "TXYZ…", "amount": "100.0001", "comment": null,
  "expires_at": "2026-09-27T12:30:00Z", "created_at": "2026-09-27T12:00:00Z", "paid_at": null, "payment": null } }

Statuses: pending → detected (payment found, waiting for confirmations) → paid (or partial if less arrived — whatever arrived is credited). A payment that comes in after expires_at is credited too.

Webhooks

Set an HTTPS URL in your account (the API tab). When you save it, you get a whsec_… secret. We then send a POST with JSON:

{ "event": "order.delivered",
  "data": { "id": "SH7K2P9Q4M", "external_id": "order-1001", "status": "delivered", … },
  "created_at": "2026-09-27T12:03:10Z" }
EventWhen
order.deliveredSteam has been topped up
order.rejectedThe top-up failed and the money went back to your balance
deposit.creditedA payment was confirmed and credited (credited_usd, balance_usd, txid)
webhook.testYou pressed “Test webhook” in your account

The X-SH-Signature header is the HMAC-SHA256 of the raw request body, keyed with your secret (hex). Reply with any 2xx code within 8 seconds; otherwise we retry after 1, 5, 15 and 60 minutes, then after 3 and 6 hours. An event can arrive more than once, so handle them idempotently (by data.id).

# Python
import hmac, hashlib
def verify(body: bytes, signature: str, secret: str) -> bool:
    calc = hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(calc, signature)

// Node.js
const crypto = require('crypto');
const ok = crypto.timingSafeEqual(
  Buffer.from(crypto.createHmac('sha256', secret).update(rawBody).digest('hex')),
  Buffer.from(req.headers['x-sh-signature']));

// PHP
$ok = hash_equals(hash_hmac('sha256', file_get_contents('php://input'), $secret), $_SERVER['HTTP_X_SH_SIGNATURE'] ?? '');

Security

  • Keep the key on your server only. If it leaks, press “Reissue” in your account — the old key stops working at once.
  • Restrict the key to your server's IP addresses in your account.
  • Verify the signature of every webhook.
