API SupplierHub

Пополняйте Steam своим клиентам автоматически. Баланс пополняется криптовалютой, заказы оплачиваются с баланса, о результате приходит вебхук.

1
Получите ключВойдите на сайт через Telegram → меню профиля → «API для партнёров» → «Создать ключ».
2
Пополните балансНа сайте или методом POST /deposits — USDT, BTC, ETH, TON и др.
3
Создавайте заказыPOST /orders списывает с баланса и пополняет Steam.

Основы

Базовый адрес: {{base}}/api/v1. Ключ передаётся в заголовке X-API-Key. Тела запросов и ответы — JSON (UTF-8). Успешный ответ содержит "ok": true, ошибка — "ok": false и текст в error.

curl {{base}}/api/v1/me -H "X-API-Key: SH-ваш_ключ"
КодЗначение
200Успешно
400Неверные параметры: текст в error, по каждому полю — в fields. Лишние поля не игнорируются, а отклоняются; суммы — строкой или числом, не больше 2 знаков после точки
401Нет ключа или ключ неверный
402Недостаточно средств на балансе — в ответе balance_usd и required_usd
403IP не в белом списке ключа или аккаунт заблокирован
404Объект не найден
429Слишком много запросов (лимит — 120 в минуту на ключ)
503Сервис временно недоступен, повторите позже

Все суммы в долларах — строки с точностью до 6 знаков ("12.249635"), чтобы не терять точность.

  "balance_usd": "250.000000", "discount": "3.75" }

GET/rates

Курсы (единиц валюты за 1 USD), ваша скидка и лимиты суммы заказа в каждой валюте.

  "discount": "3.75", "limits": { "RUB": { "min": "17", "max": "30000" }, "USD": { "min": "0.20", "max": "357.61" } } }

GET/methods

Доступные способы пополнения баланса (монета + сеть) и лимиты пополнения.

{ "ok": true, "deposit_min_usd": "0.2", "deposit_max_usd": "10000",
  "methods": [ { "code": "usdt_trc20", "coin": "USDT", "network": "TRC20", "network_title": "TRON", "confirmations": 1 }, … ] }

POST/steam/check

Проверка, можно ли пополнить Steam-аккаунт. Нужен именно логин для входа, не никнейм.

curl -X POST {{base}}/api/v1/steam/check -H "X-API-Key: SH-…" -H "Content-Type: application/json" \
  -d '{"steam_login": "mylogin"}'

{ "ok": true, "steam_login": "mylogin", "valid": true }

POST/quote

Сколько спишется с баланса за пополнение на указанную сумму.

{"amount": 1000, "currency": "RUB"}

{ "ok": true, "amount": "1000", "currency": "RUB", "nominal_usd": "11.920384", "price_usd": "11.473370",
  "discount": "3.75", "min": "17", "max": "30000", "within_limits": true }

Заказы

POST/orders

Создаёт пополнение Steam и сразу списывает стоимость с баланса.

ПолеТипОписание
steam_loginstringЛогин Steam, 3–64 символа (латиница, цифры, _ - .)
amountnumber | stringСумма зачисления в валюте currency
currencystringRUB, KZT, UAH или USD (валюта аккаунта Steam)
external_idstring, необязательноВаш ID заказа (до 64 символов). Повторный запрос с тем же ID не создаст второй заказ, а вернёт первый с "duplicate": true — безопасно повторять при таймаутах.
curl -X POST {{base}}/api/v1/orders -H "X-API-Key: SH-…" -H "Content-Type: application/json" \
  -d '{"steam_login": "mylogin", "amount": 1000, "currency": "RUB", "external_id": "order-1001"}'

{ "ok": true, "duplicate": false,
  "order": { "id": "SH7K2P9Q4M", "external_id": "order-1001", "status": "processing",
             "steam_login": "mylogin", "amount": "1000", "currency": "RUB",
             "price_usd": "11.473370", "charged_usd": "11.473370",
             "created_at": "2026-09-27T12:00:00Z", "finished_at": null, "error": null } }
СтатусЗначение
processingОплачен с баланса, пополнение выполняется
deliveredSteam пополнен
rejectedПополнить не удалось, charged_usd возвращён на баланс; причина в error

GET/orders/{id}

Заказ по нашему ID (SH…). По вашему ID — GET /orders/external/{external_id}.

GET/orders?limit=50&offset=0

История заказов, новые первыми. limit до 100.

Баланс

POST/deposits

Счёт на пополнение баланса. Отправьте ровно amount монеты на address в указанной сети в течение 30 минут — по уникальной сумме мы узнаём платёж. Для TON укажите comment в комментарии перевода.

{"amount_usd": 100, "method": "usdt_trc20"}

{ "ok": true, "deposit": { "id": "DP4M9QX2KA", "status": "pending", "usd": "100.00", "received_usd": "0.00",
  "method": "usdt_trc20", "coin": "USDT", "network": "TRC20", "network_title": "TRON",
  "address": "TXYZ…", "amount": "100.0001", "comment": null,
  "expires_at": "2026-09-27T12:30:00Z", "created_at": "2026-09-27T12:00:00Z", "paid_at": null, "payment": null } }

Статусы: pending → detected (платёж найден, ждём подтверждений) → paid (или partial, если пришло меньше — зачислено сколько пришло). Платёж, пришедший после expires_at, тоже зачисляется.

GET/deposits/{id}

GET/balance/history?limit=50&offset=0

Все движения по балансу: deposit, order (списание), refund, adjust.

{ "ok": true, "total": 3, "items": [

    "comment": "Steam mylogin: 1 000 ₽", "created_at": "2026-09-27T12:05:00Z" } ] }

Вебхуки

Укажите HTTPS-адрес в кабинете (вкладка API) — при сохранении вы получите секрет whsec_…. Мы отправим POST с JSON:

{ "event": "order.delivered",
  "data": { "id": "SH7K2P9Q4M", "external_id": "order-1001", "status": "delivered", … },
  "created_at": "2026-09-27T12:03:10Z" }
СобытиеКогда
order.deliveredSteam пополнен
order.rejectedПополнить не удалось, деньги вернулись на баланс
deposit.creditedПлатёж подтверждён и зачислен (credited_usd, balance_usd, txid)
webhook.testКнопка «Тестовый вебхук» в кабинете

Заголовок X-SH-Signature — HMAC-SHA256 сырого тела запроса вашим секретом (hex). Ответьте кодом 2xx в течение 8 секунд, иначе повторим через 1, 5, 15, 60 минут, 3 и 6 часов. События могут прийти повторно — обрабатывайте их идемпотентно (по data.id).

# Python
import hmac, hashlib
def verify(body: bytes, signature: str, secret: str) -> bool:
    calc = hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(calc, signature)

// Node.js
const crypto = require('crypto');
const ok = crypto.timingSafeEqual(
  Buffer.from(crypto.createHmac('sha256', secret).update(rawBody).digest('hex')),
  Buffer.from(req.headers['x-sh-signature']));

// PHP
$ok = hash_equals(hash_hmac('sha256', file_get_contents('php://input'), $secret), $_SERVER['HTTP_X_SH_SIGNATURE'] ?? '');

Безопасность

  • Храните ключ только на сервере. При утечке — «Перевыпустить» в кабинете, старый сразу перестанет работать.
  • Ограничьте ключ IP-адресами своего сервера в кабинете.
  • Проверяйте подпись каждого вебхука.
