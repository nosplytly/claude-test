# Запуск: что сделать руками

Код и проверки готовы. Эти шаги требуют твоих аккаунтов — их никто, кроме тебя, не сделает.
В конце `tools\preflight.py` покажет, всё ли на месте.

## 1. Секреты — только на сервере

Архив `supplierhub-deploy.zip` теперь **без секретов**: его можно пересылать и хранить где угодно.
Секреты лежат отдельно в папке `Desktop\supplierhub-secrets\` (`.env` и `certs\`).

1. Один раз скопируй эту папку на сервер в `C:\supplierhub\` поверх (через RDP, не через мессенджеры и почту).
2. Удали её с рабочего стола и старые архивы с секретами.
3. При обновлениях копируешь только новый архив — `.env` и `certs\` на сервере не трогаются.

## 2. Новые токены перед запуском

Старые ключи лежали в архивах и проходили через чаты. Перед запуском выпусти новые:

- **Бот:** @BotFather → `/revoke` → выбери бота → новый токен в `BOT_TOKEN` на сервере.
- **Nervixy:** кабинет → API-ключ → перевыпустить → новый ключ в `NERVIXY_API_KEY`.
- **Сертификат:** если архив с `privkey.pem` уходил кому-то кроме тебя — перевыпусти его у GlobalSign.

После правки `.env`: `powershell -ExecutionPolicy Bypass -File .\deploy\windows\update.ps1`

## 3. Ключи блокчейнов (бесплатные)

Без них публичные сервисы режут запросы, и платежи при потоке клиентов распознаются с опозданием.

| Ключ в `.env` | Где взять |
|---|---|
| `TRONGRID_API_KEY` | trongrid.io → регистрация → API Keys → Create |
| `TONCENTER_API_KEY` | бот @tonapibot в Telegram → получить ключ toncenter |
| `TONAPI_KEY` | tonconsole.com → TonAPI → ключ (вторая проверка платежей в TON) |

## 4. Вебхук Nervixy

Без него статусы заказов узнаются опросом — медленнее и тратит лимит Nervixy.

1. Кабинет Nervixy → **Настройки → Webhooks**.
2. URL: `https://sh-control-universe.com/api/webhooks/nervixy`
3. Скопируй секрет `whsec_…` (показывается один раз) в `NERVIXY_WEBHOOK_SECRET` на сервере, выполни `update.ps1`.
4. В кабинете нажми «Отправить тестовое событие» — должно прийти 200.

## 5. IP сервера в белом списке Nervixy

Nervixy принимает запросы только с разрешённых IP. Добавь IP сервера в кабинете.
`preflight.py` скажет, если IP не в списке.

## 6. База PostgreSQL

Ставится сама: запусти `install.ps1` как обычно. Он скачает PostgreSQL 18 (официальная сборка EDB), создаст
службу `supplierhub-postgres` (только 127.0.0.1), базу и пользователя, впишет `DATABASE_URL` и `PG_BIN` в `.env`
и **перенесёт данные из SQLite** — в одной транзакции, со сверкой строк и балансов. Старый файл остаётся рядом
как `supplierhub.sqlite3.moved-to-postgres-…`. Пароль суперпользователя `postgres` — в `data\postgres-superuser.txt`
(нужен только для восстановления из бэкапа, см. `tools\restore_backup.py`).

Бэкапы с этого момента — `pg_dump` (файл `….dump.gz.enc` в Telegram), восстановление тем же инструментом с `--into`.

## 7. Проверка

На сервере, в `C:\supplierhub`:

```
.venv\Scripts\python.exe tools\preflight.py --live
```

Зелёные галочки — готово. Красное — что исправить и почему. `--live` дополнительно проверяет вторые
источники платежей на настоящих свежих транзакциях всех сетей.
