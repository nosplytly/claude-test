# SupplierHub — бот для Playerok

<img src="supplierhub/web/assets/logo.svg" width="72" alt="SupplierHub">

Автоматизация продаж на [playerok.com](https://playerok.com):

- **Автовыдача товара.** Как только покупатель оплатил заказ, бот отправляет ему в чат
  товар из файла (ключ, аккаунт, код) или заранее заданный текст и отмечает сделку выполненной.
- **Уведомления в Telegram:** новые продажи, выдача товара, подтверждения, возвраты и жалобы,
  закончившийся товар, сообщения от покупателей.
- **Перевыставление лотов.** Проданный лот снова выставляется на продажу, а лоты с истёкшим
  сроком публикуются заново. Используется только бесплатный тариф.

Бот работает через неофициальную библиотеку [PlayerokAPI](https://pypi.org/project/PlayerokAPI/).
Playerok её не поддерживает: если площадка изменит API, обновите библиотеку
(`pip install -U PlayerokAPI`).

Всем этим можно управлять в приложении **SupplierHub** с окном и кнопками, а можно запускать
бота из консоли с настройками в файле.

## Приложение SupplierHub (Windows)

Окно с шестью разделами:

- **Главная**: работает ли бот, кнопка «Запустить» / «Остановить», продажи, выручка и выданный
  товар за сегодня, лента событий, товары, которые заканчиваются.
- **Продажи**: последние сделки и история автовыдачи. Видно, кто что купил и что получил.
  Сделки с ошибкой выдачи или без товара собраны в фильтре «Требуют внимания».
- **Автовыдача**: правила для лотов и склад товара по каждому правилу. Товары можно добавлять
  списком, загружать из `.txt` и удалять. Перед сохранением видно, какое сообщение получит покупатель.
- **Перевыставление**: что и когда выставлять заново.
- **Настройки**: токен Playerok с кнопкой проверки, Telegram с тестовым сообщением, интервалы и прокси.
- **Журнал**: подробный лог работы бота.

### Как получить SupplierHub.exe

1. Установите [Python 3.11+](https://www.python.org/downloads/). В установщике отметьте
   **Add python.exe to PATH**.
2. Скачайте этот репозиторий (Code → Download ZIP) и распакуйте его.
3. Дважды щёлкните `build_windows.bat`. Он сам поставит зависимости и соберёт приложение.
4. Готовое приложение появится в папке `dist\SupplierHub`: запускайте `SupplierHub.exe`.
   Эту папку можно перенести куда угодно.

Если собирать не хочется, запустите `SupplierHub.bat`. При первом запуске он сам поставит
нужные пакеты (около минуты) и откроет окно.

### Первый запуск

1. **Настройки → Playerok**: вставьте токен (как его найти, написано ниже) и нажмите «Проверить».
2. **Настройки → Telegram** (по желанию): токен бота и ваш chat id, затем «Отправить тест».
3. **Автовыдача → Новое правило**: часть названия лота и сообщение с `{product}`. Затем
   **Склад → Добавить товары**.
4. **Главная → Запустить**.

Все данные лежат рядом с программой: `config.toml` (настройки), `state.json` (кому и что выдано),
`stock\` (товар) и `bot.log`. Кнопка «Открыть папку» в настройках открывает эту папку.

Для окна нужен компонент Microsoft Edge WebView2. Он уже есть в Windows 10 и 11. Если его нет,
SupplierHub откроется во вкладке браузера и будет работать так же. Закрывать программу в этом
случае нужно кнопкой «Выйти» внизу боковой панели: просто закрыть вкладку недостаточно.

Бот работает, пока открыт SupplierHub. Окно можно свернуть. Если закрыть его при работающем
боте, программа спросит подтверждение.

## Установка (для запуска из консоли)

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt
```

Скопируйте `config.example.toml` в `config.toml` и заполните его по шагам ниже.

### 1. Токен Playerok

1. Войдите в аккаунт на playerok.com в браузере.
2. Откройте DevTools (F12) → **Application** (в Firefox: **Хранилище**) → **Cookies** →
   `https://playerok.com`.
3. Скопируйте значение cookie `token` в `playerok.token`.

Токен даёт полный доступ к аккаунту. Не публикуйте `config.toml` (он уже в `.gitignore`)
и никому его не пересылайте. Токен можно не писать в файл, а передать через переменную
окружения `PLAYEROK_TOKEN`. Если вы выйдете из аккаунта в браузере, токен перестанет
работать. Бот пришлёт об этом уведомление.

### 2. Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и вставьте его токен в `telegram.bot_token`.
2. Узнайте свой числовой id у [@userinfobot](https://t.me/userinfobot) и впишите его в `telegram.chat_ids`.
3. **Напишите своему боту `/start`**, иначе Telegram не разрешит ему писать вам первым.

### 3. Товар для автовыдачи

Для каждого лота добавьте правило `[[delivery.rules]]`:

```toml
[[delivery.rules]]
match = "Ключ Steam"                 # часть названия лота, регистр не важен
stock_file = "stock/steam_keys.txt"  # одна строка = один товар
message = "Спасибо, {buyer}! Ваш ключ: {product}"
products_per_sale = 1                # сколько строк выдавать за покупку
low_stock_alert = 3                  # предупредить, когда останется ≤ 3
```

- Выданная строка удаляется из файла, и второй раз её никто не получит. Бот помнит выданное:
  если строка вернётся в файл (например, вы сохранили старую копию в Блокноте), он её пропустит
  и предупредит. Поэтому одинаковые строки считаются одним товаром.
- Многострочный товар пишите в одну строку через `\n`: `логин: user\nпароль: 123`.
- Подстановки в `message`: `{product}` — товар, `{buyer}` — ник покупателя, `{item}` — название лота.
- Правило без `stock_file` отправляет всем покупателям один и тот же текст (например, ссылку).
- Правила проверяются сверху вниз, и срабатывает первое подходящее. Более точные `match` ставьте выше.

Пример файла склада лежит в `stock/example.txt`. Файлы в `stock/` в git не попадают.

### 4. Проверка

```bash
python -m playerok_bot --check
```

Команда проверит токен, покажет количество товара по каждому правилу и отправит
тестовое сообщение в Telegram.

## Запуск

```bash
python -m playerok_bot
```

Остановить бота можно через Ctrl+C. Лог пишется в консоль и в `bot.log`, подробный лог
включается флагом `-v`.

Бот должен работать постоянно. Для этого подойдёт VPS: пример юнита systemd
(`/etc/systemd/system/playerok-bot.service`):

```ini
[Unit]
Description=Playerok bot
After=network-online.target

[Service]
WorkingDirectory=/opt/playerok-bot
ExecStart=/opt/playerok-bot/.venv/bin/python -m playerok_bot
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now playerok-bot
journalctl -u playerok-bot -f
```

## Как это работает

**Источники событий.** Каждые `deals_interval` секунд бот запрашивает последние продажи.
Этот опрос не даст пропустить сделку, даже если WebSocket отвалится. Сам WebSocket
(`use_websocket`) нужен для мгновенной реакции. Сообщения из чатов бот получает опросом
раз в `messages_interval` секунд.

**Автовыдача** срабатывает на продажу в статусе «оплачено» (`PAID`):

1. Товар берётся из файла и сразу записывается в `state.json`, и только потом отправляется
   покупателю. Если бот упадёт посередине, после перезапуска он отправит тот же товар,
   а не возьмёт новый.
2. Если отправить не удалось, бот повторит попытку при следующей проверке. После 5 неудач
   он пришлёт в Telegram товар для ручной выдачи.
3. Если товар закончился, сделка ждёт. Пополните файл, и бот выдаст товар сам.
4. При `mark_sent = true` после выдачи сделка отмечается выполненной.

**Первый запуск.** Сделки, которые уже были оплачены до первого запуска, бот не трогает:
возможно, вы уже выдали по ним товар вручную. Их список придёт в Telegram. Лоты по этим
продажам бот тоже не перевыставляет. Сделки, оплаченные, пока бот был выключен (при уже
существующем `state.json`), обрабатываются после запуска.

**`state.json`** хранит сведения о том, кому и что выдано. Не удаляйте этот файл:
без него бот снова посчитает запуск первым.

**Перевыставление** (`[relist]`):

- `after_sale`: проданный лот публикуется заново один раз на каждую продажу. По умолчанию
  так перевыставляются только лоты с правилом автовыдачи. Лот без правила обычно уникален
  (например, конкретный аккаунт), и продать его дважды нельзя. Если товара в `stock_file`
  не осталось, лот тоже не перевыставляется: так вы не продадите то, чего нет. Лоты с запасом
  на несколько продаж и так остаются в продаже, их бот не трогает.
- `expired`: раз в `interval_minutes` бот ищет ваши лоты с истёкшим сроком и публикует их заново.
- `match`: перевыставлять только лоты с указанными словами в названии. Лоты, названные здесь,
  перевыставляются после продажи, даже если у них нет правила автовыдачи.

Платное поднятие (PREMIUM/VIP) на Playerok списывает деньги с баланса, поэтому бот его не
покупает. Лот, который был на платном тарифе, перевыставится на бесплатном.

## Разработка

```bash
pip install -r requirements-dev.txt -r requirements-gui.txt
python -m pytest
```

Тесты используют поддельный аккаунт и в сеть не ходят. Тесты интерфейса (`tests/ui`) запускают
Chromium через Playwright. Без него они пропускаются.

Приложение можно открыть в обычном браузере: `python -m supplierhub --browser`. Ключ `--workdir`
задаёт папку с данными. Скриншоты всех экранов на тестовых данных делает команда
`python tests/ui/screenshots.py --out shots`.

```
supplierhub/        приложение SupplierHub
├── app.py          окно (pywebview), режим браузера, командная строка
├── api.py          методы, которые вызывает интерфейс
├── runtime.py      бот в отдельном потоке: запуск, остановка, статус
├── configio.py     настройки, правила и склад из окна
├── server.py       локальный сервер для режима браузера (с токеном)
├── stats.py        продажи и показатели для главной
├── feed.py         лента событий и журнал
└── web/            интерфейс: index.html, app.css, js/
playerok_bot/
├── __main__.py   запуск, аргументы командной строки, логирование
├── bot.py        сборка бота и проверка --check
├── config.py     чтение и проверка config.toml
├── watchers.py   слежение за сделками (опрос + WebSocket) и сообщениями
├── delivery.py   автовыдача
├── relist.py     перевыставление лотов
├── stock.py      файлы с товаром
├── storage.py    state.json
└── telegram.py   уведомления
```
