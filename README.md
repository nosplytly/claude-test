# SupplierHub — пополнение Steam криптовалютой

Сайт `sh-control-universe.com`: клиент входит через Telegram, пополняет Steam со скидкой и платит криптой
на **наши собственные кошельки** (без процессинга). Пополнение выполняет поставщик [nervixy](https://nervixy.digital/docs-api).
Есть баланс сайта, пополнение баланса и API для партнёров.

```
клиент ──► сайт ──► счёт с уникальной суммой ──► платёж в блокчейне ──► мониторинг сетей
                                                                   │
            Telegram-бот ◄── уведомления ◄── заказ ◄── баланс ◄────┘ ──► nervixy api_order ──► Steam
```

## Как устроено

* **Один процесс** (`run.py`): FastAPI-сайт + Telegram-бот + мониторинг блокчейнов + обработчик заказов + бэкапы.
  База — SQLite (`data/supplierhub.sqlite3`), бэкап раз в сутки в `data/backups` (хранится 14).
* **Оплата:** на каждый счёт выдаётся уникальная сумма (`12.2537 USDT`), по ней платёж узнаётся автоматически.
  Для TON дополнительно используется комментарий (memo) с номером заказа. Если клиент прислал чуть другую сумму
  (биржа удержала комиссию), а открытый счёт в этой сети один — платёж сопоставится по близости (±10%).
  Всё остальное — «неопознанный платёж»: админу приходит алерт, клиент может прислать хэш, админ подтверждает кнопкой.
* **Приватных ключей на сервере нет** — только публичные адреса. Взлом сервера не даёт вывести деньги.
* **Деньги клиента** всегда проходят через баланс: платёж → зачисление на баланс → списание за заказ.
  Отказ поставщика, поздний платёж, переплата → остаются на балансе. Каждое движение пишется в журнал (`ledger`).
* **Поставщик:** если nervixy не ответил на создание заказа — заказ не отправляется повторно вслепую, а ищется
  в их истории по `partner_id`; если не найден за 5 минут — админу приходит выбор «повторить / вернуть на баланс».
  Нехватка средств у поставщика → заказ ждёт в очереди, админу алерт. Сайт не даёт создать заказ больше, чем
  хватает на балансе nervixy.

### Сети и источники данных (все бесплатные)

| Метод | Сеть | Откуда берём данные | Подтверждения |
|---|---|---|---|
| USDT TRC20, TRX | TRON | TronGrid | solidified (~1 мин) |
| USDT TON, TON | TON | toncenter v3 (USDT ищется на нашем настоящем jetton-кошельке) | финальность сразу |
| USDT BEP20 | BSC | publicnode RPC | 15 блоков |
| USDT SOL, SOL | Solana | публичный RPC | finalized |
| USDT ERC20, ETH | Ethereum | publicnode RPC | 12 блоков |
| BTC | Bitcoin | mempool.space → blockstream → blockchair | 1 |
| LTC | Litecoin | litecoinspace → blockcypher → blockchair | 3 |

Для стейблкоинов курс 1:1. Для BTC/ETH/LTC/TON/TRX/SOL курс берётся с Binance (запасные: OKX, Bybit, CoinGecko)
плюс наценка `VOLATILE_MARKUP` (0.5%) на конвертацию и волатильность.

## Лимиты nervixy

API nervixy жёстко ограничивает частоту запросов («Слишком много попыток. Подождите 60 секунд»), а попытки
во время бана, похоже, его продлевают. Поэтому клиент (`app/nervixy.py`):

* шлёт запросы строго по одному с паузой `NERVIXY_MIN_INTERVAL` (3 с);
* после 429 молчит 65 с и никуда не стучится, всё это время отдаёт закэшированные курсы и баланс;
* статусы всех заказов в работе проверяет **одним** запросом истории раз в 20 с (с вебхуком nervixy почти не нужно);
* баланс поставщика перечитывает раз в ~5 минут, а после каждого заказа уменьшает его локально.

Точные цифры лимитов стоит уточнить у поддержки nervixy и, если можно, подкрутить `NERVIXY_MIN_INTERVAL`.
Тест этой логики: `.venv\Scripts\python tests\test_nervixy_limits.py`.

## Деньги: откуда маржа

Клиенту скидка `CLIENT_DISCOUNT` (3.75%), у нас от nervixy — 4.5%. Маржа ≈ 0.75% от номинала.
Комиссию сети платит отправитель. Партнёрам можно дать свою скидку: `/disc @user 4.0` в боте
(выше скидки поставщика бот не даст).

## Настройка (.env)

Образец — `.env.example`. Главное:

* `NERVIXY_API_KEY` — ключ nervixy; IP сервера должен быть в их белом списке.
* `BOT_TOKEN` — токен бота от @BotFather. `ADMIN_TG_IDS` — твой Telegram ID (узнать: @userinfobot).
* `WALLET_*` — **публичные** адреса кошельков. Пустой адрес = способ оплаты скрыт.
  Лучше завести отдельный некастодиальный кошелёк под магазин (Trust Wallet / Tonkeeper / Phantom и т.п.).
  ⚠️ Адреса бирж для TON и некоторых сетей требуют memo — для приёма они **не подходят**.
  ⚠️ TON-кошелёк лучше «активировать» (сделать с него одну исходящую транзакцию).
* `NERVIXY_WEBHOOK_SECRET` — секрет вебхука из панели nervixy (URL: `https://<домен>/api/webhooks/nervixy`).
* `SUPPORT_URL` — ссылка «Поддержка» на сайте.

## Локальный запуск

Проще всего — двойной клик по `start-local.cmd`: остановит старый сервер на порту 8000 (спросит), при первом
запуске создаст `.venv`, откроет http://localhost:8000. Вручную:

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env   # ENV=dev, NERVIXY_MOCK=true, MONITOR_ENABLED=false для игры без денег
.venv\Scripts\python run.py
```

В dev-режиме без `BOT_TOKEN` есть «Dev-вход», а при `NERVIXY_MOCK=true` — кнопка «Симулировать оплату».
Логин с `bad` — невалидный, с `reject` — поставщик отклонит заказ.

Тест денежной логики (свежая временная база, без реальных сетей и денег):

```powershell
.venv\Scripts\python tests\test_money_flow.py
```

## Деплой на Windows VDS

1. Скопировать папку проекта на сервер, например `C:\supplierhub` (без `.venv` и `data`).
2. Положить сертификат: `certs\fullchain.pem` (сертификат + цепочка) и `certs\privkey.pem`.
3. Заполнить `.env` (`ENV=prod`, `BASE_URL=https://sh-control-universe.com`, `NERVIXY_MOCK=false`).
4. PowerShell **от администратора**:
   ```powershell
   cd C:\supplierhub
   powershell -ExecutionPolicy Bypass -File .\deploy\windows\install.ps1
   ```
   Скрипт ставит Python (если нет), зависимости, скачивает Caddy (HTTPS) и WinSW, регистрирует две службы
   с автозапуском и перезапуском при падении (`supplierhub-app`, `supplierhub-caddy`), открывает порты 80/443,
   закрывает доступ к ключу сертификата и `.env`, проверяет что всё отвечает.
5. DNS: A-записи `sh-control-universe.com` и `www` → IP сервера. В nervixy добавить IP сервера в белый список.

Обновление после замены файлов: `.\deploy\windows\update.ps1`. Логи: `data\logs\`.
Сертификат GlobalSign действует до **05.02.2027** — заменить файлы в `certs\` и перезапустить `supplierhub-caddy`.

## Telegram-бот

* Клиенты: вход на сайт (кнопка с кодом), уведомления об оплате/пополнении/возвратах, `/balance`, `/orders`.
* Админы (`ADMIN_TG_IDS`): алерты (новые заказы, нехватка баланса nervixy, неопознанные платежи, проблемы сетей),
  кнопки «повторить / вернуть на баланс», подтверждение заявок по хэшу,
  `/stats`, `/bal <tg_id|@user> [+/-сумма] [комментарий]`, `/disc <tg_id|@user> <процент|reset>`.

## API для партнёров

Документация: `https://<домен>/api-docs`. Ключ создаётся в кабинете (меню профиля → «API для партнёров»).
Коротко: `X-API-Key`, `POST /api/v1/deposits` — пополнение баланса криптой, `POST /api/v1/orders` — пополнение
Steam с баланса (идемпотентно по `external_id`), вебхуки `order.delivered / order.rejected / deposit.credited`
с подписью HMAC-SHA256.

```
    callbacks.py     все callback-кнопки, типизированные (их же используют алерты в orders/monitor)

    common.py        Screen и show(), фильтр админа · queries.py запросы к базе для экранов
  notify.py          отправка уведомлений в Telegram
  tgui.py            эмодзи, цветные кнопки, откат на обычные эмодзи
  avatars.py         аватарки из Telegram для шапки сайта (кэш в data/avatars, нет фото — буква)
  webhooks.py        вебхуки партнёрам
  payments/
    methods.py       список монет/сетей
    invoices.py      счета с уникальной суммой
    monitor.py       опрос сетей, сопоставление, зачисление, заявки по хэшу
    chains/          tron, evm, ton, solana, utxo (btc/ltc)
  web/               index.html, docs.html, assets (css/js/шрифты/иконки)

tests/               test_money_flow.py, test_bot_offline.py, test_nervixy_limits.py, test_avatars.py
```
